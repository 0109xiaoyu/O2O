# O2O优惠券个性化投放预测与业务策略分析
> 基于用户、商户、优惠券多维特征的机器学习建模与业务决策支持 —— 从探索性分析、特征工程到模型评价与决策闭环的完整分析流程

[![XGBoost](https://img.shields.io/badge/XGBoost-分类-orange)]()

O2O平台每年发放大量优惠券，但核销率普遍偏低，投放成本浪费严重。本项目基于某O2O平台的历史数据，围绕 **探索性分析 → 数据预处理 → 特征工程 → 模型训练 → 模型评价 → 业务决策闭环** 六个递进目标，构建"用户—商户—优惠券"三位一体的多维度建模框架，并通过 **GroupKFold 按用户分组** 的方式从源头阻断数据泄漏，为投放策略提供可信的量化依据。

| 问题 | 目标 | 方法 |
|:---:|:---|:---|
| Q1 | 识别用户消费、领券、商户投放、距离分布特征 | 描述性统计 + 可视化 |
| Q2 | 清洗数据、统一日期与折扣率格式 | 缺失值处理 + 类型转换 |
| Q3 | 从用户/商户/优惠券三维度构建特征 | 业务驱动的特征工程 |
| Q4 | 构建分类模型预测核销概率 | 决策树 + XGBoost |
| Q5 | 评估模型效果并提取关键因子 | 准确率/精确率/召回率/F1 + 特征重要性 |
| Q6 | 制定投放策略、实现决策闭环 | 阈值权衡 + 增量重训 |

## 2. 数据清洗与质量控制

1. **空值处理**：将 `'null'` 字符串统一替换为 `NaN`，避免字符串污染数值计算；
2. **日期解析**：`date_received` 和 `date` 统一为 `datetime` 类型，`date` 允许空值（表示未核销）；
3. **折扣率统一**：将满减形式 `'150:20'` 转换为折扣率 `0.87`，与原折扣率统一为数值；
4. **标签构建**：`diff_days = date - date_received`，`diff_days <= 15` 记为核销（class=1），否则为 0；
5. **样本剔除**：剔除 `coupon_id` 为空的记录（未领券样本不参与建模）；
6. **防泄漏切分**：采用 **GroupKFold 按 user_id 分组**，确保同一用户的所有记录只出现在训练集或验证集中，杜绝重叠泄漏。

## 3. 特征工程（用户 / 商户 / 优惠券三维度）

### 3.1 用户维度（5个特征）

| 特征 | 含义 |
|------|------|
| user_use_coupon_times | 用户使用优惠券消费次数 |
| user_consume_times | 用户总消费次数 |
| user_use_coupon_rate | 用券消费 / 总消费 |
| user_receive_coupon_unused_times | 领券未使用次数 |
| user_mean_use_coupon_interval | 平均用券间隔天数 |

### 3.2 商户维度（5个特征）

| 特征 | 含义 |
|------|------|
| merchant_launch_coupon_used_count | 商户发券被使用数 |
| merchant_launch_coupon_used_rate | 商户发券被使用率 |
| merchant_launch_coupon_count | 商户发券总数 |
| merchant_receive_unused | 商户发券未使用数 |
| merchant_mean_launch_coupon_interval | 商户发券平均核销间隔 |

### 3.3 优惠券维度（2个特征）

| 特征 | 含义 |
|------|------|
| coupon_fifteen_used_count | 15 天内核销数（优惠券流行度） |
| coupon_used_rate | 券使用率 |

合并后共 **14 个特征**（含 distance、discount_rate 等原始字段），构建模型输入矩阵。

## 6. 构建模型（含 GroupKFold 防泄漏）

### 6.1 为什么用 GroupKFold

- 随机切分会导致**同一用户跨集**，模型可能"记住"用户的历史行为，形成重叠泄漏；
- **GroupKFold 按 user_id 分组**，确保同一用户的全部记录只出现在训练集或验证集。

### 6.2 模型参数

| 模型 | 参数 |
|------|------|
| 决策树 | max_leaf_nodes=16, random_state=123 |
| XGBoost | max_depth=8, learning_rate=0.1, n_estimators=160, objective='binary:logistic' |

### 6.3 GroupKFold 5 折交叉验证结果

**决策树：**

|:---:|:---:|:---:|:---:|:---:|

| 2 | 0.9620 | 0.7154 | 0.6091 | 0.6579 |
| 3 | 0.9622 | 0.7106 | 0.6033 | 0.6526 |
| 4 | 0.9608 | 0.7184 | 0.5843 | 0.6445 |
| 5 | 0.9618 | 0.7188 | 0.6154 | 0.6631 |
| **均值** | **0.9616** | **0.7173** | **0.5979** | **0.6521** |

**XGBoost：**

| Fold | 准确率 | 精确率 | 召回率 | F1 |
|:---:|:---:|:---:|:---:|:---:|

**结论**：XGBoost 在各项指标上均优于决策树，F1 均值高出 0.07。

## 7. 模型评价

### 7.1 独立验证集评估

按 `user_id` 分组切分：训练集 663,679 条、验证集 283,600 条，正样本率保持一致（约 6%）。

| 模型 | 准确率 | 精确率 | 召回率 | F1 |
|------|:---:|:---:|:---:|:---:|
| 决策树 | 0.9610 | 0.6877 | 0.6422 | 0.6642 |
| **XGBoost** | **0.9712** | **0.8015** | **0.6932** | **0.7434** |

**XGBoost 分类报告：**

| 类别 | 精确率 | 召回率 | F1 | 样本数 |
|:---:|:---:|:---:|:---:|:---:|
| 0（未核销） | 0.9806 | 0.9890 | 0.9848 | 266,558 |
| 1（核销） | 0.8015 | 0.6932 | 0.7434 | 17,042 |
| macro avg | 0.8910 | 0.8411 | 0.8641 | 283,600 |
| weighted avg | 0.9698 | 0.9712 | 0.9703 | 283,600 |

### 7.2 特征重要性 Top5

| 排名 | 特征 | 重要性（gain） |
|:---:|------|:---:|
| 1 | user_mean_use_coupon_interval | **554.08** |
| 2 | user_receive_coupon_unused_times | 178.72 |
| 3 | user_use_coupon_times | 53.10 |
| 4 | merchant_receive_unused | 43.39 |
| 5 | distance | 27.80 |

**结论**：
- **用户平均用券间隔**是最强预测因子——说明"用户的用券习惯"对是否核销有决定性影响；
- 用户领券未使用次数、用户用券次数紧随其后，说明用户历史行为是关键；
- **距离**重要性相对较低（27.80），说明在本数据中位置不是决定因素。

## 8. 问题五：业务策略与决策闭环

### 8.1 客群分层与精准投放

- 按用户历史用券率与消费频次划分"高活跃高用券""高活跃低用券""低活跃高用券""低活跃低用券"四类；
- 高核销概率用户优先推券，低潜客群减少投放或改推高吸引力券种。

### 8.2 商户经营优化

- 头部商户发券量大但核销率参差不齐；
- 对高核销率商户倾斜流量资源，对低核销率商户联合营销或调整券种。

### 8.3 优惠券产品优化

- 用户用券间隔对核销影响最大，距离影响相对较弱；
- 建议设计"爆款券"提升券本身吸引力，而不是单纯依赖"附近推送"。

### 8.4 阈值权衡与预算分配

在独立验证集上对比不同阈值下的模型效果：

| 阈值 | 发券比例 | 精确率 | 召回率 | F1 | 适用场景 |
|:---:|:---:|:---:|:---:|:---:|:---|
| 0.3 | 7.90% | 0.6629 | **0.8714** | 0.7529 | 拉新期，覆盖优先 |
| **0.4** | 6.43% | 0.7356 | 0.7868 | **0.7604** | **推荐默认值（F1 最优）** |
| 0.5 | 5.20% | 0.8015 | 0.6932 | 0.7434 | 平衡点 |
| 0.6 | 4.06% | 0.8682 | 0.5866 | 0.7002 | 平衡偏精准 |
| 0.7 | 3.20% | **0.9227** | 0.4910 | 0.6410 | 预算紧张期，精准优先 |

**关键洞察**：阈值从 0.3 提到 0.7，精确率从 0.663 提升到 0.923（每一张券几乎都不浪费），但召回率从 0.871 降到 0.491（漏掉一半真实核销用户）。**F1 在 0.4 处达到最优（0.7604）**，是推荐默认值。

### 8.5 决策闭环

1. **数据**：新一期用户行为数据接入；
2. **模型**：用历史 + 新数据增量重训；
3. **策略**：按预算动态调整阈值；
4. **反馈**：收集实际核销结果，评估策略效果；
5. **迭代**：形成"数据—模型—策略—反馈"闭环。

**新旧模型对比（验证集）：**

| 模型 | 准确率 | 精确率 | 召回率 | F1 |
|------|:---:|:---:|:---:|:---:|
| 旧模型 | 0.9712 | 0.8015 | 0.6932 | 0.7434 |
| **新模型（增量重训）** | **0.9713** | **0.8038** | 0.6916 | **0.7435** |

**结论**：闭环重训后模型整体效果保持稳定，F1 略有提升（0.7434 → 0.7435）。

### 8.6 业务解读

- 模型不是"投或不投"的开关，而是在**有限预算下的优先级排序工具**；
- 不同业务阶段（拉新、留存、清库存）应选择不同阈值：
  - **拉新期**：选 0.3-0.4，覆盖优先，抢占更多转化机会；
  - **平稳期**：选 0.5，精确率与召回率平衡；
  - **预算紧张期**：选 0.6-0.7，精准优先，只投最可能核销的用户；
- 漏掉高潜用户的代价 > 多投一张券的成本，需根据实际 ROI 权衡。
